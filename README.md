# Mail Configuration Checker

ドメインを入力すると、メールの受信やなりすまし対策に関係する設定をまとめて確認できるWebアプリです。

DNSレコードを表示するだけではありません。設定に問題がないかを診断し、問題がある場合は次に確認することを案内します。診断結果は、技術者向けと顧客向けの2種類の文章でコピーできます。

## なぜ作ったのか

仕事でメール設定を確認するときは、次の作業を何度も行っていました。

```text
設定を調べる
↓
問題があるか確認する
↓
次に何を確認するか考える
↓
相手に分かりやすく伝える
```

MX・SPF・DMARCを別々に調べ、取得した情報から問題を判断し、その結果を相手に合わせて説明するには手間がかかります。

そこで、この流れをできるだけ1つの画面で進められるように、このアプリを作りました。

## 何ができるのか

### MXレコードの確認

- メールを受信するサーバーが設定されているか確認する
- 複数ある場合は、優先度順に表示する
- メールを受信しないことを示すNull MXを判定する

### SPFレコードの確認

- メールの送信元を確認する設定があるか調べる
- SPFレコードが複数ある場合に注意を表示する
- `include` の数を表示する
- `-all`、`~all`、`?all`、`+all` などの終端設定を表示する

### DMARCレコードの確認

- なりすましメール対策の設定があるか調べる
- `p=none`、`p=quarantine`、`p=reject` を読み取り、それぞれの意味を表示する
- DMARCレコードが複数ある場合に注意を表示する

### DNSエラーの表示

DNS情報を取得できなかった場合も、できるだけ原因が分かるメッセージを表示します。

- ドメインが見つからない
- DNS情報が設定されていない
- DNSサーバーで一時的なエラーが発生した
- DNS問い合わせがタイムアウトした
- その他の理由で取得できなかった

### 次に確認すること

診断結果に問題がある場合は、結果を表示するだけでなく、次に確認した方がよい内容も案内します。

たとえば、次のような案内を表示します。

- MXレコードがない場合は、利用中のメールサービスから指定された設定を確認する
- SPFレコードがない場合は、TXTレコードへの追加を確認する
- SPFレコードが複数ある場合は、1つにまとめる
- SPFの終端設定が `+all` または未設定の場合は、設定を見直す
- DMARCが未設定の場合は、追加を検討する
- DMARCが `p=none` の場合は、今後設定を強くするか検討する

問題の内容に応じて、「参考」「要確認」「優先対応」に分けて表示します。優先して確認する項目がない場合も、そのことが画面で分かります。

### 診断結果のコピー

診断結果は、用途に合わせて2種類の文章でコピーできます。

#### 技術者向け

MX・SPF・DMARCの状態、診断メッセージ、実際のDNSレコードなど、設定を詳しく確認できる文章です。

#### 顧客向け

専門用語をできるだけ減らし、設定に詳しくない方にも伝えやすくした文章です。

```text
メールの受信設定は正常です。
メールの送信元を確認する設定が登録されています。
なりすましメール対策の設定が未登録です。必要に応じて追加設定をご検討ください。
```

## 利用の流れ

1. `example.com` のような形式でドメインを入力する
2. 「診断する」を押す
3. MX・SPF・DMARCの設定を確認する
4. 診断結果を表示する
5. 問題がある場合は、次に確認する内容を表示する
6. 必要に応じて、技術者向けまたは顧客向けの診断結果をコピーする

## 実装で工夫したこと

### 結果を見ただけで終わらないようにした

DNSレコードを表示するだけでは、設定に詳しくない方は次に何をすればよいか判断しにくいことがあります。

そのため、次の流れまで分かるようにしました。

```text
何が設定されているか
↓
問題があるか
↓
次に何を確認するか
```

### 技術者向けと顧客向けで文章を分けた

同じ診断結果でも、相手によって必要な情報は異なります。

技術者向けにはDNSレコードなどの詳しい内容を含め、顧客向けには専門用語を減らしています。仕事で調査結果を説明するときに、相手に合わせて文章を変えていた経験をもとに追加した機能です。

### 処理を役割ごとに分けた

すべての処理を1つのファイルに書かず、役割ごとに分けています。

```text
dns.ts
DNS情報を取得して、設定内容を確認する

domain.ts
入力されたドメインの形式を確認する

format-result.ts
コピーする文章を作る

recommendations.ts
次に確認する内容を作る

DnsResultCard.tsx
診断結果を表示する
```

機能を追加するときに、どこを変更すればよいか分かりやすくするためです。

### 待ち時間を短くした

MX・SPF・DMARCの確認は互いに独立しているため、3つのDNS情報を並行して取得しています。

### 入力内容を2か所で確認した

ドメインの形式は、画面側とAPI側の両方で確認しています。APIが画面以外から呼び出された場合も、正しくない入力をDNS問い合わせへ渡さないようにしています。

## 使用技術

| 分類 | 使用技術 |
| --- | --- |
| フレームワーク | Next.js 16（App Router） |
| 画面 | React 19 |
| 言語 | TypeScript |
| 見た目の調整 | Tailwind CSS 4 |
| DNS情報の取得 | Node.js `node:dns/promises` |
| コードの確認 | ESLint |

## API

### `POST /api/check`

入力されたドメインのMX・SPF・DMARCを確認し、診断結果をJSONで返します。

リクエスト例：

```json
{
  "domain": "example.com"
}
```

## セットアップ

### 必要な環境

- Node.js 20.9以上
- npm

### インストールと起動

```bash
git clone https://github.com/git-yuji/mail-checker-app.git
cd mail-checker-app
npm install
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開きます。

### 品質確認

```bash
npm run lint
npm run build
```

## 現在の制限

次の内容には、まだ対応していません。

- DKIMの確認
- SPFのDNS Lookup回数と10回制限の確認
- SPFの `include` 先まで詳しく確認する処理
- DMARCの組織ドメインへのフォールバック
- DMARCレポート設定の確認
- 診断履歴の保存

診断結果は参考情報として利用してください。実際にDNSやメール設定を変更する場合は、利用中のサーバー会社やメールサービスの公式情報も確認してください。
